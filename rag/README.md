# RAG (Retrieval-Augmented Generation) 미니 프로젝트

검색(Retrieval)과 생성(Generation)을 결합해 LLM이 주어진 문서를 바탕으로 답하도록 만든 프로젝트.
무료 오픈소스 모델만으로 RAG 파이프라인을 처음부터 구현하고, RAG의 장점과 한계를 직접 실험으로 검증했다.

## 사용 기술
- Python, sentence-transformers, Hugging Face `transformers`, PyTorch
- 임베딩 모델: `jhgan/ko-sroberta-multitask` (한국어 문장 임베딩)
- 생성 모델: `Qwen/Qwen2.5-1.5B-Instruct` (무료 오픈소스 LLM)

## 구조
```
[문서들] → 임베딩 벡터 변환 → 저장
                                  ↑
[질문] → 임베딩 벡터 변환 → 코사인 유사도 비교 → 관련 문서 검색
                                  ↓
        [질문 + 검색된 문서] → LLM → 답변 생성
```

## 진행 과정

### 1. 검색(Retrieval) 구현
- 문장 임베딩으로 문서와 질문을 벡터화, 코사인 유사도로 가장 관련 있는 문서 검색
- **임베딩 모델 선택의 중요성 발견**: 영어 전용 모델(`all-MiniLM-L6-v2`)로 한국어 문서를 검색하니 의미와 무관하게 문장 구조가 비슷한 문서가 상위에 뜨는 오작동 확인 → 한국어 지원 모델로 교체 후 정상화
- 질문 형태(의문문 vs 서술문)도 검색 정확도에 영향을 준다는 점 관찰

### 2. 생성(Generation) 연결
- 검색된 문서를 프롬프트에 "참고 자료"로 포함시켜 LLM에 전달
- API 비용 없이 진행하기 위해 무료 오픈소스 모델(Qwen2.5-1.5B-Instruct)을 GPU로 직접 실행

### 3. 핵심 실험 — RAG의 효과 검증
같은 질문("RAG는 뭐야?")을 RAG 있을 때/없을 때로 비교:

| 조건 | 결과 |
|---|---|
| RAG 사용 | "검색과 생성을 결합한 자연어 처리 기법" — **정확** |
| RAG 미사용 | "Relevance-Aware Gating의 약자" — **완전히 지어낸 오답 (hallucination)** |

→ 검색된 정확한 문서를 참고 자료로 제공하면, 작은 모델도 훨씬 신뢰할 수 있는 답변을 생성함을 확인.

### 4. 핵심 실험 — RAG의 한계 검증 (거짓 정보 주입 테스트)
documents에 의도적으로 틀린 정보를 넣고 RAG가 이를 그대로 따르는지 테스트:

| 주입한 거짓 정보 | 모델 반응 |
|---|---|
| "1+1은 3이다" | ✅ 거부 — "1+1은 2입니다" (정답 유지) |
| "세종대왕은 고려의 왕이었다" | ❌ 그대로 따름 — 거짓 정보 반복 |
| "김치는 중국에서 기원했다" | ❌ 그대로 따름 — 거짓 정보 반복 |

→ 모델은 **절대적이고 예외 없는 지식(수학)**에는 검색 문서보다 자기 지식을 우선했지만, **암기 기반 지식(역사, 문화)**은 검색된 문서를 그대로 신뢰함.

## 핵심 인사이트

**RAG는 정확도를 높여주지만 만능이 아니다.**
- RAG는 LLM이 모르거나 불확실한 정보에 대해 훨씬 정확한 답을 하게 해줌 (hallucination 감소)
- 그러나 검색된 문서 자체가 틀렸을 경우, 모델이 이를 스스로 검증하지 않고 **그대로 신뢰해 오류를 증폭**시킬 수 있음 ("garbage in, garbage out")
- 모델이 오류를 거부하는 경우는 매우 확고한 사전지식(수학적 사실 등)과 충돌할 때뿐이며, 실무에서 다루는 대부분의 정보(회사 정책, 제품 스펙, 역사적 사실 등)는 이 범주에 들지 않음
- **결론**: RAG 시스템의 신뢰성은 결국 검색되는 문서의 품질 관리에 달려있다. LLM이 알아서 오류를 걸러줄 것이라고 기대해서는 안 된다.

## 배운 점 (다음 단계에 적용)
- 임베딩 기반 유사도 검색은 지난 NLP 프로젝트의 워드 임베딩 개념이 문서 단위로 확장된 것
- 프롬프트에 "참고 자료를 바탕으로 답하라"는 지시는 강제가 아니라 가이드라인 — 모델의 사전지식과 충돌 시 결과 예측 불가
- 실제 서비스에 RAG를 적용하려면 문서 품질 검증, 출처 신뢰도 관리가 모델 성능만큼 중요함# RAG (Retrieval-Augmented Generation) 미니 프로젝트
